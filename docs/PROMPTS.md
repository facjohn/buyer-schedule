# Claude Code 단계별 지시문

아래 상자 안 글을 순서대로 하나씩 Claude Code에 붙여 넣습니다. 한 단계가 끝나면 아이폰으로 확인하고 다음으로 넘어갑니다.
한 번에 다 시키지 않는 게 핵심입니다. 단계가 작을수록 Claude Code가 짐작하는 부분이 줄어듭니다.

2026-10-14에 단순화 방향(산지 정보·역할·보낸 기록 없음, 작업비 칸, 시즌별 단가 흐름)으로 고쳤습니다. 0단계 계획은 그날 끝났습니다.

## 1단계: 구글시트와 Apps Script

창구(Apps Script)의 동작은 이 단계에서 한꺼번에 만듭니다. 뒤 단계는 화면만 붙이면 되게 하려는 것입니다.

```text
1단계를 만들어 줘.
- Apps Script는 구글시트에 붙은 스크립트로 만들어 시트 ID를 코드에 쓰지 않게 하고, apps-script/ 폴더에서 clasp로 관리해. .clasp.json은 .gitignore에 넣어. appsscript.json의 웹 앱 설정은 실행: 배포한 사람(USER_DEPLOYING), 접근: 로그인 없이 누구나(ANYONE_ANONYMOUS).
- setup() 함수 하나를 돌리면 탭(스케줄, 바이어, 품목, 스펙, 팀원, 숨긴 탭 로그)과 머리글, 드롭다운(바이어, 과일, 운송, 상태, 회사), 머리글 보호, id 열 숨김, 품목 첫 등록값이 한 번에 만들어지게 해. 열은 SPEC 개발용 메모 표를 따라.
- seedSample() 함수로 예시 데이터(바이어 A~F, 스케줄 줄, 스펙 사전, 단가 흐름을 볼 수 있게 지난 시즌 줄 몇 개)를 넣어 줘. 예시 팀원 2명의 코드는 실행할 때 무작위로 만들어 나에게만 보여 주고, 코드 파일에는 적지 마. 나중에 한 번에 지울 수 있게 clearSample()도.
- 시트 메뉴에 "팀원 코드 만들기"를 넣어 줘. 12자 이상 무작위 코드를 만들어 팀원 탭에 넣고, 그 코드가 들어간 앱 링크(앱 주소#code=...)를 나에게 보여 줘.
- 요청은 모두 POST로 받고, 본문은 JSON 문자열을 text/plain으로 받아(브라우저 CORS 사전 요청을 피하려고). 동작은 list, save, remove, prices 네 개(SPEC 개발용 메모 표).
- 모든 요청에서 접속 코드를 팀원 탭과 대조해. 틀린 코드는 데이터 없이 거절하고 로그 탭에 남겨(10분 안의 반복은 한 줄로 묶어 횟수만). 맞는 코드는 언제나 통과시켜.
- 저장은 LockService로 한 번에 하나씩, 바뀐 칸만, 수정자와 수정 시각을 남겨. id와 No.는 잠금 안에서 창구가 붙여(CLAUDE.md 절대 규칙 5).
- 시트에서 직접 고친 줄도 수정자("시트")와 수정 시각이 남게 해.
- clasp로 올리고 배포하는 방법을 내 컴퓨터 기준으로 단계별로 알려 줘. 내가 브라우저에서 직접 해야 하는 일(구글 로그인, Apps Script API 켜기, 처음 권한 허용)은 따로 표시해 줘. 다음에 고칠 때 같은 배포를 새 버전으로 갱신하는 명령도(설치된 clasp 버전에 맞게).
```

확인할 것: 시트에 탭 6개(하나는 숨김)와 머리글이 생겼는지, 틀린 코드는 거절되고 로그 탭에 남는지, 같은 바이어에 새 줄을 저장하면 No.가 최댓값 + 1인지(지운 번호를 다시 쓰지 않는지), 시트에서 줄을 복사해 붙여도 id가 겹치지 않는지, 저장소에 시트 ID나 접속 코드가 들어가지 않았는지.

## 2단계: 홈, 바이어 스케줄, 스케줄 입력

```text
2단계를 만들어 줘. Vite + React로 프런트를 시작하고, docs/mockups/의 01, 02-schedule-ko, 03과 html 폴더의 같은 이름 파일에 화면을 맞추되, docs/DESIGN.md의 "시안과 달라진 점"을 우선해.
- 접속: 링크(#code=...)로 열면 코드를 그 폰에 저장하고 주소창에서 바로 지워. 링크 없이 열면 코드 넣는 화면이고, 코드만 넣어도 되고 초대 링크를 통째로 붙여 넣어도 되게. 코드가 거절되면 다시 읽기를 멈추고 이 화면으로 돌아와.
- 홈: 숫자 세 칸(7일 안 ETA, 미정 건, 산지가 빈 건), 바이어 카드(다음 ETA 가까운 순, 일정 없는 바이어는 아래, 남은 선적 수는 No. 기준), 검색, 시트 열기(list가 준 주소, 없으면 숨김), +, 아래 메뉴 2칸(스케줄, 단가).
- 바이어 스케줄: 한 건 두 줄(윗줄 No.·과일·운송·스펙, 아랫줄 ETA·바이어가·산지가, 작업비는 산지가 아래 작게), 월별 묶음(올해가 아니면 해 표시), 기간(다음 2개월, 앞으로 전부, 지난 일정)과 과일 필터. 줄을 누르면 수정, 길게 누르면 같은 컨테이너에 사이즈 추가·다음 선적으로 복제·지우기.
- 허용 칸 변환 함수(JPG용)는 지금 한 곳에 만들어 두고 4단계 JPG가 같은 함수를 쓰게.
- 스케줄 입력: 한 화면에 한 줄. No.는 '새 번호'가 기본이고(예상 번호만 보이고 확정은 창구가), '같은 컨테이너'를 고르면 그 바이어의 기존 No. 중에서. 같은 컨테이너 추가는 같은 No.에 같은 값, 다음 선적 복제는 새 번호에 날짜·산지가를 비움. 스펙 영어는 사전에서 자동, 없으면 한 번 받아 사전에 추가. 바이어가는 같은 바이어·과일·스펙의 직전 값. 산지가와 작업비는 비워 두고 직전 값 안내 칩만. ETA가 상차일보다 이르면 저장 전에 경고. 칸 순서는 바이어·No. → 과일 → 운송 → 산지 → 스펙·영어 → 상차일·ETA → 산지가·작업비 → 바이어가·상태. 회사·수량·메모 칸은 두지 마(시트에서).
- 앱은 30초마다 다시 읽고, 저장 직후에는 바로 다시 읽어.
- 이번 단계에서 Apps Script를 고쳤으면 clasp로 올리고 기존 배포를 새 버전으로 갱신해.
- 개발 서버를 같은 와이파이의 아이폰에서 열 수 있게 띄우는 방법도 알려 줘.
끝나면 아이폰에서 확인할 목록을 줘. 특히 폭 360px에서 가로 스크롤이 생기지 않는지.
```

확인할 것: 아이폰에서 표가 옆으로 밀리지 않는지, 앱에서 저장한 게 시트에 바로 들어가는지, 링크로 연 뒤 주소창에 코드가 남지 않는지, 홈 화면에 추가한 앱에서 초대 링크를 붙여 넣어 들어가지는지, 복제로 같은 컨테이너에 사이즈를 더하면 같은 No.가 붙는지.

## 3단계: 단가 흐름

```text
3단계를 만들어 줘. docs/mockups/07과 docs/DESIGN.md의 "시안과 달라진 점"에 맞춰.
- 버튼 줄 셋: 과일, 시즌(품목 탭 시즌 시작 월 기준, 기본은 이번 시즌), 바이어(전체 + 그 과일·시즌에 일정이 있는 바이어).
- 스펙마다 카드: 바이어가와 산지가 그래프 두 개(라이브러리 없이 SVG), 마지막 값과 직전 대비 변화, 오늘 점선(이번 시즌일 때만). 바이어를 고르면 그 바이어 값만. 전체에서는 같은 날 여러 값은 점으로 다 찍고 선은 평균으로, 바이어가는 통화마다 따로.
- 작업비는 그래프에 넣지 말고 목록의 산지가 밑에 작게.
- 목록: ETA · 바이어 · 바이어가 · 산지가, 날짜 내림차순, 오늘 구분선, 미정 표시.
- 데이터는 prices 동작으로 그 과일의 모든 시즌을 받아.
끝나면 아이폰 확인 목록을 줘.
```

확인할 것: 바이어를 바꾸면 그 바이어 값만 그려지는지, 시즌 버튼으로 지난 시즌 값이 보이는지, 같은 날 두 바이어 값이 있어도 선이 지그재그로 꺾이지 않는지, 작업비가 그래프에 섞이지 않는지.

## 4단계: JPG, 배포

```text
4단계를 만들어 줘. docs/mockups/의 04, 08과 docs/DESIGN.md의 바이어용 JPG 항목, "시안과 달라진 점"에 맞춰.
- JPG 전용 컴포넌트를 만들어. 화면 캡처가 아니라 2단계의 허용 칸 변환 함수가 만든 데이터만 받아서 그려. 폭 1080px, 높이는 줄 수만큼(최소 1350px). 이미지로 바꿀 때 pixelRatio는 1로 해서 결과 파일도 정확히 폭 1080px로.
- 통화와 가격 줄은 바이어 탭에서, 회사명은 줄의 회사에서. 기간 안에 두 회사 물량이 섞이면 미리보기 위에 회사 버튼을 두고 회사별로 JPG를 따로 만들어.
- JPG 미리보기: 기간(이번 달, 2개월, 앞으로 전부), 바이어가 표시. 미리보기가 뜰 때 이미지를 미리 만들어 두고, 한글 글꼴 로딩이 끝난 뒤 만들어.
- 공유: navigator.share({ files })로 파일만 넘기고, 미리보기 이미지를 길게 눌러 사진 앱에 저장할 수 있게. 공유가 안 되는 기기는 다운로드.
- 테스트: JPG 컴포넌트에 넘기는 데이터에 허용 목록 밖의 키가 없는지, 그린 결과의 글자에 ₩, 산지 이름, 수량, 메모 예시 값이 하나도 없는지, 결과 이미지 폭이 1080px인지.
- 홈 화면 추가용 manifest와 아이콘, GitHub Actions로 GitHub Pages 배포.
- 이번 단계에서 Apps Script를 고쳤으면 clasp로 올리고 기존 배포를 새 버전으로 갱신해.
끝나면 실제 아이폰 확인 목록을 줘: 홈 화면 추가, 접속 코드 유지, JPG 공유, 길게 눌러 저장, 줄이 많은 JPG, 두 사람 동시 수정.
```

확인할 것: 받은 JPG를 바이어 입장에서 열어 봤을 때 산지가·작업비가 어디에도 없는지, 왓츠앱과 카톡으로 실제로 보내지는지, 20줄이 넘는 JPG도 빈 이미지 없이 만들어지는지.

## 실제로 쓰기 전에

- seedSample로 넣은 예시 데이터를 clearSample로 지우고 실제 바이어, 품목 시즌 시작 월, 팀원을 넣습니다. 바이어 탭에는 통화, 가격 단위, 가격 조건, 기본 회사까지 채웁니다.
- 팀원마다 시트 메뉴의 "팀원 코드 만들기"로 코드를 만들고, 나온 링크를 그 사람에게만 보냅니다. 아이폰에서는 홈 화면에 추가한 뒤 그 앱에서 링크를 한 번 더 붙여 넣습니다. 퇴사하거나 담당이 바뀌면 팀원 탭에서 그 줄을 지웁니다.
- 시트 공유는 PC로 일하는 직원 계정만 이름으로 추가하고, 링크 공유는 꺼 둡니다.
- 시트에서 줄을 복사해 붙일 때는 id 칸을 비워 둡니다(새 선적이면 No.도 비움). 줄을 없앨 때는 행을 삭제하지 말고 삭제 칸에 체크합니다.
- 일주일쯤 시트와 앱을 같이 보면서 숫자가 맞는지 확인합니다.

## 막혔을 때

- 에러 메시지는 그대로 붙여 넣습니다.
- 화면이 시안과 다르면 시안 이미지 경로를 다시 주고 "이 부분을 시안처럼 맞춰 줘"라고 합니다.
- Apps Script를 고쳤는데 앱이 예전처럼 움직이면, 웹 앱을 새 버전으로 다시 배포했는지 확인합니다. 새 배포를 만들지 말고 기존 배포를 새 버전으로 고쳐야 웹 앱 주소가 그대로입니다.
- 길게 헤매면 새 세션을 열고 "CLAUDE.md와 docs를 읽고 지금 상태부터 이어서"라고 시작합니다. 규칙은 CLAUDE.md에 있어서 새 세션도 같은 기준으로 일합니다.
